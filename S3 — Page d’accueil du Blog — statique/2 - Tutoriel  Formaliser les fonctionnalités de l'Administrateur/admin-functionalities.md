# Admin Functionalities – Blog

## Goal
Change the Admin raw actions into clear functionalities.

Use this rule:

**Actor + Action + Element**

Organize functionalities by entity.

## 1. Naming rule by entity

### Articles
- The Admin lists articles.
- The Admin adds an article.
- The Admin changes an article.
- The Admin deletes an article.

### Categories
- The Admin lists categories.
- The Admin adds a category.
- The Admin changes a category.
- The Admin deletes a category.

## 2. Functional journey – example

Functionality: **The Admin adds a category.**

- **Actor:** Admin
- **Start screen:** Category management page
- **Action:** Click "Add a category"
- **Result:** Show the category creation form

## 3. Functional synthesis

| Actor | Functionalities |
|---|---|
| Admin | **Articles:**<br>- List articles<br>- Add an article<br>- Change an article<br>- Delete an article<br><br>**Categories:**<br>- List categories<br>- Add a category<br>- Change a category<br>- Delete a category |

## 4. CRUD check

Both entities follow CRUD:

| Letter | Action | Simple meaning |
|---|---|---|
| C | Create | Add new data |
| R | Read | See data list |
| U | Update | Change data |
| D | Delete | Remove data |

## Result
The Admin can manage **Articles** and **Categories**.

For each entity, the Admin can:

- See the list.
- Add new data.
- Change data.
- Delete data.

All functionalities follow the **CRUD** model.
